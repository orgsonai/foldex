## 保存（1.8.2 / code 92）

### 保存前の準備

`ImageExportCoordinator` が、描画、エンコード、メタデータの反映、出力の検査を行ってから保存先へ渡す。

- `DocumentRenderer` は成功 Bitmap と失敗理由を分ける。素材の解決・デコード・変形に失敗した場合、不完全な画像を成功として返さない。
- 読み込み時の原本の SHA-256 と、書き出し前後の内容を照合する。編集中に別の内容へ変わったときは保存を止める。
- 固定名の一時ファイルを使わず、書き出しごとに一意な一時ファイルを作る。
- 出力形式、画素寸法、縮小デコードの成否、SHA-256、メタデータを含む最終容量を確認する。
- 目標容量に収まらない場合は保存を止め、寸法または目標容量の変更を案内する。
- 撮影情報の引き継ぎに失敗した場合は、画像の保存成功とは別に知らせる。
- キャンセルを通常の保存失敗へ潰さない。書き出し準備と保存先選択の一時ファイルの所有者を明示する。

### ローカルの原本保護

上書きは同形式の既知の拡張子（jpg / jpeg / png / webp）に限る。たとえば `photo.png` を JPEG に変換する場合、別の `photo.jpg` を上書きすることはない。

上書きでは、原本と同じディレクトリに一時ファイルを作り、コピー・sync・内容照合を終え、原本の変更を再確認してから原子的に置き換える。原子的な置き換えが使えない場合、原本を直接開いて上書きする方法へは移行せず、別名保存を案内する。

別名保存は `CREATE_NEW` で排他的に作成する。同名があれば連番へ進み、作成競合で他のファイルを消さない。書き込み後に内容を検証する。途中失敗の後片付けは、同じファイルの識別子を確認できる場合に限る。

### NAS と Android の文書保存先

- NAS の保存は原本を残す新規コピーにする。元のフォルダ内へ、元名と一意な識別子を含むファイル名で出力する。
- 保存先の安全な置換を共通インターフェースで保証できないため、NAS / SAF の原本上書きは今回の保存画面では提供しない。
- SAF から開いた画像も別名保存できる。「保存先を選んで保存」から Android の新規文書作成を使う。他の保存元からも利用できる。
- 保存先選択は、画像の生成・検査が終わってから開く。キャンセルでは準備した一時出力を破棄し、編集へ戻る。
- 書き込み・close の後に同じ出力を読み戻し、SHA-256 が一致した場合だけ保存成功にする。
- 通信断などで確認できない場合は「保存結果を確認できません」を表示。「再確認」は同じ URI を読み直すだけで、再送しない。
- 内容が不一致なら成功にせず、コピーが不完全である可能性と対象の名前を知らせる。元のファイルを削除・変更しない。

### 実装上の限界と次段階

- 原本変更の確認とローカル置換の間には、他のアプリが書き込める短い間隔が残る。全アプリを含めた条件付き更新ではない。
- NAS の新規コピーは、現在は一意な最終名へ直接送信する。途中のコピーが一時的に見えたり、通信断・プロセス終了後に不完全なコピーが残ったりする場合がある。リモート一時名からの公開と、サーバー別の条件付き置換は後続。
- FTP / WebDAV の既存 `CREATE_NEW` は、サーバーでの原子的排他を保証しない。一意な新規名により既存名との衝突を避けている。厳密な排他はストレージ実装の別課題。
- 原本・一時出力の検査は、色・見た目を実機で評価する代わりにはならない。デコードできることだけで、あらゆる入力破損を検出できるとは扱わない。
- 保存と容量見積もりの元画像キャッシュは処理後に解放するが、端末全体のメモリ予算・巨大画像のタイル処理は未実装。
- 下書きの永続化、プロセス終了後の保存再確認の復元、選択ブラシ、写真補正、合成機能は次段階。今回の実装をそれらの完了扱いにはしない。
