## 保存画面と出力の変更

| 項目 | 振る舞い |
|---|---|
| JPEG の背景 | 白を既定に、白・黒または任意の RGB 色を選択。保存画面に背景色のプレビューを表示 |
| 透明化した部分 | 全レイヤーを描いた後に JPEG の背景を合成。透明化で背景まで消えて黒くなる問題を避ける |
| PNG / WebP | JPEG 用の背景色を適用せず、透過を保持 |
| 透過の判定 | 不透明／透明あり／未確認を区別。不透明 JPEG がキャンバス全体を覆うときは透過の警告を出さない |
| 撮影情報 | 「撮影情報・位置情報を保持」「撮影情報を保持・位置情報を除く」「共有用：撮影情報・位置情報を含めない」を選択 |
| 設定の保持 | 背景色・撮影情報・容量上限を編集セッションの出力設定へ保持。保存画面を開き直したり、画像操作を Undo/Redo したりしても、位置情報の除外を取り消さない |
| 容量上限 | JPEG / WebP に加えて PNG でも指定可能。空欄や 0 のまま容量指定を有効にした場合は保存ボタンを無効にし、容量指定を勝手に外さない |
| 容量超過 | 最終容量と縮小候補を表示。「このサイズに変更」「容量指定を外して保存」「編集に戻る」を選べる |

縮小候補の適用では編集内容・撮影情報・背景・容量上限を保持し、再度「保存」を選ぶ。容量指定を外すボタンは、上限を解除して元の保存方法で再実行することを明示する。どちらも利用者の選択前には適用しない。

## 透過と色

`Transparency` と画像の配置から、不透明だと断定できる範囲を判定する。透過の可能性が残る場合は、プレビューを一行ずつ走査する。64×64 の間引き検査を廃止し、検査する Bitmap 内では一画素の透明部分も調べる。ただし、縮小前にしか存在しない小さい穴はプレビューでは判別できないため、検査結果が不透明でも原寸を不透明とは断定しない。

JPEG の背景は `ExportPixels` が最終描画へ `DST_OVER` で合成する。下地を先に塗る方式ではないため、後から追加した透明化レイヤーにも対応する。JPEG の実出力には常に背景を合成し、警告表示の判定だけに依存しない。容量計測と保存も同じ処理を通す。

入力は sRGB へのデコードを要求し、異なる色空間や精度で返った場合は sRGB・ARGB_8888 の画像へ描き直す。出力キャンバスも sRGB・8ビットとする。入力の ICC を出力へそのままコピーして、画素と色の指定を食い違わせない。[BitmapFactory の色空間指定](https://developer.android.com/reference/android/graphics/BitmapFactory.Options#inPreferredColorSpace)

保存画面では HDR・広色域を引き継がないことを明示する。API 34 以降で入力に gainmap があれば、SDR のベース画像を使い、gainmap は出力に持ち込まない。Ultra HDR はベース画像と gainmap を持つため、その両方を編集する高度な対応とは区別する。[Ultra HDR の編集](https://developer.android.com/media/grow/ultra-hdr/edit)

## 撮影情報

既定は従来どおり位置情報も保持する。保持する撮影情報は、日時・機種・作者・著作権・レンズ・露出など、`ExifTransfer.CAPTURE_TAGS` に列挙した対応項目に限る。

- GPS は緯度・経度だけでなく、方向、測地系、移動速度、目的地、地域情報なども分離する。「位置情報を除く」では GPS の項目をコピーしない。
- 共有用では元ファイルの撮影情報を読み込まず、新しく符号化した画素に必要な出力情報だけを付ける。
- 元ファイルの XMP、MakerNote、埋め込みサムネイル、古い寸法・向きはコピーしない。共有用は撮影情報の除外であり、写り込んだ内容やファイル名を匿名化する機能ではない。
- 向きは画素へ適用済みとして Orientation=1、色空間は sRGB、寸法は実出力の幅・高さへ更新する。
- 反映後に EXIF を読み直し、対応タグの保持・除外を確認する。反映できなかった場合は画像保存後にその旨を知らせる。

AndroidX ExifInterface は JPEG・PNG・WebP の属性書き込みを提供する。対応する撮影情報を新規出力へ反映し、原本へ直接適用しない。[ExifInterface](https://developer.android.com/reference/androidx/exifinterface/media/ExifInterface#saveAttributes())

## 容量の計測と再試行

容量の表示は、JPEG 背景・選択した撮影情報まで適用した一時ファイルから測る。圧縮データ全体をアプリの配列へ保持せず、計測後は一時ファイルを削除する。入力中の連続計測は 250ms の待機でまとめる。

JPEG / WebP の目標容量では、品質候補ごとに撮影情報を反映したファイル全体を測る。探索で採用した品質が現在の一時ファイルと異なる場合は再生成し、最終検査とハッシュ取得の後に容量を再確認する。圧縮サイズの単調性を成功の根拠にはせず、実際に上限内の出力だけを保存先へ渡す。

PNG は品質値で容量を調整しない。実測値が上限を超えれば、他形式と同じ縮小候補へ進める。候補は実測容量からの概算で、必ず達成する寸法という保証ではない。メタデータの固定量や画像内容によって再調整が必要になり、再保存時も最終容量を検査する。長辺 16px まで縮小済みなら、さらに縮小する候補は出さない。

メモリ判定と全編集画面共通の実行枠は維持する。保存準備が成功するまでは、ローカル・NAS・SAF の保存先に書き込まない。
