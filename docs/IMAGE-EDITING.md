## 実装済み: 選択範囲のモザイク

画像ビューアの「編集」→「選択」で矩形・楕円・投げ縄を使って範囲を選ぶ。
「追加」「除外」で範囲を修正し、「モザイク」で粒度の調整画面に入る。
プレビューを確認して「適用」で確定する。「キャンセル」または戻る操作で調整を破棄できる。
適用後は既存の Undo / Redo で取り消し・やり直しができる。

- 粒度は画像の短辺に対する 0.5〜8%（最小 2px）。既定は 2.5%。
- 調整中の操作は履歴に積まず、適用時に一手だけ記録する。
- 元画像と `Layer.Mosaic` の指示を保持し、プレビューと保存で同じレンダラーを使う。
- モザイク範囲は切り抜き・90度回転・反転に追従する。
- 各ブロックの全画素を平均し、透明画素の隠れた RGB は平均に混ぜない。
- 半透明画像でも元の細部が重ならないよう、対象の画素を置換する。
- ブロック単位で処理し、出力画像全体の追加コピーを作らない。
- スライダー操作は 100ms のデバウンスと描画キャンセルを行う。
- 描画中の元画像キャッシュが別の処理に解放されないよう貸し出しを同期する。
- 調整中の保存、プレビュー失敗時の適用、保存中の編集を抑制する。

## 実装済み: 人物・物のタップ自動選択

「選択」→「人物・物」で、対象の内側をタップして輪郭を推定する。
選択結果を確認してからモザイク・塗りつぶし・透明化へ進める。
複数の対象は「追加」、不要な部分は「除外」。矩形・楕円・投げ縄での手動修正にも対応する。
2 本指はこれまでどおりズーム・移動として扱い、自動選択を発火させない。

- 同梱した MagicTouch revision 1 を **LiteRT 1.4.2 の同梱版 CPU 推論**で実行する。
- 画像・利用統計を送信せず、モデルを実行時にダウンロードしない。
- 背景処理中は進捗とキャンセルを表示する。失敗時は前の選択を保持する。
- 連打は前の処理をキャンセルし、同時推論は 1 件に制限する。
- 選択解除、ツール変更、画像の編集、Undo / Redo、画面終了で古い結果を破棄する。
- 推論に渡す画像は、切り抜き・回転・既存の編集を反映した専用の縮小画像。
  UI の Bitmap を推論側から解放しない。
- 輪郭は論理座標の多角形として保存し、穴や離れた部分を保持する。
  保存時に再推論して範囲を変えることはしない。
- ノイズの多い結果には輪郭点数の上限を設け、複雑なパスでメモリを使い切ることを防ぐ。
- 推論器は各処理の終了時に閉じる。初期化を毎回行う代わりに、画面終了時にも
  ネイティブメモリの所有者が曖昧にならない構成にした。

### ライセンスと実装方式

2026-09-13、ユーザーから「ライセンスが変わらないなら追加して問題ありません」と承認済み。
旧設計の依存追加禁止に対する、この機能の例外として実装した。
**Foldex 本体は MIT のまま**。追加部品にはそれぞれのライセンスを維持する。

| 部品 | バージョン | ライセンス・告知 |
|---|---|---|
| LiteRT / LiteRT API | 1.4.2 | Apache 2.0。配布 AAR の LICENSE を変更せず同梱（Caffe 由来の BSD 告知も含む） |
| MagicTouch | float32 / revision 1 | Apache 2.0。配布元、作者、SHA-256、ライセンス全文を同梱 |

設定のライセンス画面から両方の全文・告知を読める。
モデルの詳細は `app/src/main/assets/models/README.md` に記録している。
根拠: [LiteRT 配布 POM](https://dl.google.com/dl/android/maven2/com/google/ai/edge/litert/litert/1.4.2/litert-1.4.2.pom)、
[MagicTouch モデルカード](https://storage.googleapis.com/mediapipe-assets/Model%20Card%20MagicTouch.pdf)、
[Apache 2.0 の再配布条件](https://www.apache.org/licenses/LICENSE-2.0#redistribution)。

当初候補だった MediaPipe 0.10.35 の配布版には DataTransport と統計送信処理があるため、
採用を変更した。Gradle の実行時依存には MediaPipe、DataTransport、Play services を追加していない。
LiteRT 同梱版でモデルを直接実行する。

### 追加の検証と限界

- 実モデルのハッシュ、実際のテンソル形状、正規化・点指定・出力の解釈を確認した。
  配布モデルは `[1,512,512,1]` の sigmoid 適用済み確率を返す。
  モデルカードの「2 チャネルの logits」をそのまま実装しないようにした。
- 3×3 の全 512 マスクパターンで、穴・離れた領域・斜めに接する画素を検証した。
- ズーム・パン・余白を含むタップ座標変換、輪郭の回転、追加・除外、キャンセルをテストした。
- Google 公開の猫・人物のサンプル画像に対し、同じ入力形式で実モデルを実行した。
  猫と、人物写真内の異なる 2 人をタップしたマスクを目視確認した。
  これはデスクトップの Python LiteRT 2.2.0 での確認であり、Android 実機検証とは別。
  サンプル画像は検証用の一時領域のみで、アプリやリポジトリには含めない。
- 同梱するネイティブライブラリは arm64-v8a / armeabi-v7a / x86 / x86_64 の全 ABI で
  ELF LOAD セグメントの 16KB アラインメントを確認した。
- モデル解像度は 512×512。髪や細い物の境界を完全に切り抜ける保証はない。
  利用者が適用前に範囲を確認・修正できる操作を維持する。
- Android 実機での初回待ち時間、連続タップ、キャンセル、回転後の保存、低メモリ動作、
  画面回転・バックグラウンド復帰の確認は残る。商用出荷の判定は実機評価後に行う。
