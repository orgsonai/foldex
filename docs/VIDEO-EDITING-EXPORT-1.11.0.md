## 書き出しの流れ

1. 描画計画（`plan/RenderPlanner`）を作る。書き出せない構成はここで止め、書き出し画面に理由を出す
2. 素材を確認する。追加したときのサイズ・更新時刻と比べ、削除・差し替え・権限切れなら止める
3. 空き容量を確認する（見積もりの 1.1 倍 + 32MiB）
4. Transformer で一時ファイルへ書き出す（診断データ無効）
5. 読み戻して検証する。音声トラック、映像トラックと寸法、先頭・中間・末尾のコマの復号
6. 容量指定で目標を超えたら、ビットレート × 目標 ÷ 実際 × 0.95 で最大 2 回書き出し直す
7. 素材をもう一度確認してから、保存先へ配置する
8. 結果を出す: 保存 / 保存したが条件未達（寸法・コーデック・長さ・容量を要求と実際で並べる）/ 失敗（理由ごとの案内）/ 取消

| 保存先 | 方式 |
|---|---|
| 素材と同じフォルダ | そのフォルダの隠しファイル `.foldex-export-<uuid>.part` へ書き出す。空の `<名前>_edited.mp4` を排他的に作り、改名で置き換える。数 GB でもコピーしない。同じ名前があれば `_edited2` … |
| 場所を選ぶ（SAF） | アプリのキャッシュに書き出してから、選んだ文書へ書き込む。閉じた後に読み戻して SHA-256 を照合し、合わなければ文書を消す |

原本には一切書き込まない。途中で止まったら一時ファイルを消す。
プロセスが終了した場合は、記録（`filesDir/videoedit/export-journal.txt`）をもとに、次に編集画面を開いたときに片付けて知らせる。

## 対応したもの

| 項目 | 書き出しでの扱い |
|---|---|
| メインのクリップ | 区間、速度（音程を保つかを含む）、90° 回転と左右反転、はめ込む／埋める |
| 静止画 | 表示秒数。書き出しの fps でコマを作る |
| 音声 | 16bit・2ch に統一（3ch 以上は音の大きさを保つ係数で 2ch に）。音量 0〜200%、ミュート、直線のフェード |
| 音声トラック | 重なるクリップは別の段に分けてミックス |
| 文字 | プレビューと同じ比率（太字・高さ × 大きさ・縁取り 12%）の画像を、表示区間だけ重ねる |
| 書き出し設定 | 標準・高画質・容量指定・音声のみ（.m4a）。解像度・fps（上限）・H.264 / HEVC・音声のビットレート |
| HDR | API 29 以降は SDR に変換して揃える |
| 書き出し中 | 前景サービス（Android 15 以降は mediaProcessing、14 以前は dataSync）と部分 WakeLock。通知に進捗と取消。Android 15 以降の時間上限で止める |

## 未対応・割り切り

- 背景色: はめ込みの余白は常に黒になる。書き出し画面で知らせる
- 映像の終わりより後ろの音声・文字は書き出さない。書き出し画面で知らせる
- 無劣化カットと位置情報の項目は未実装のため、画面から外した
- 端末の能力（対応する寸法・fps・コーデック）による選択肢の絞り込みは未実装。合わない設定は Media3 が切り替え、結果で「条件未達」と表示する
- 長さの許容差は暫定（3 コマか 0.1 秒の大きい方）。受け入れ条件（1 コマ以内）は実機で計測して詰める
- NAS の素材と保存先、プロジェクトの保存、音の出るプレビュー（CompositionPlayer）は未実装

## 実機で確認が要る前提

ソースから判断して実装したが、実機では確かめていない点。

| 設計書の番号 | 前提 | 根拠（Media3 1.11.1 のソース） |
|---|---|---|
| U1 | 文字の表示区間は、合成全体の効果に届く時刻を出力の先頭からの時刻として判定する | SequenceAssetLoader が各素材の時刻に、前の素材の長さの合計を足している |
| U4 | 44.1kHz と 48kHz の混在は Transformer が揃える | AudioGraphInput がクリップの音声処理の後にサンプルレートを変換する |
| U5 | 縦長の出力は、回転情報を反映した表示の向きで検証する | Transformer は縦長を横長の画素と回転情報で保存する |
| U7 | フェードの時刻は速度変更の後の時刻で計算する | 速度変更は読み込み段階（SpeedChangingMediaSource）で行われ、音声処理より前 |
| — | 静止画・音声の無い動画の区間は無音になる | 音声を含むシーケンスでは SequenceAssetLoader が無音を補う |
| — | compileSdk 36 で既存コードが壊れない | 公開メソッドの削除が無いことは javap で確認。null 許容の注釈の変化はビルドで確認 |

## 実機で確かめること

1. 既存の再生の回帰（Media3 1.11.1 への更新のため）: 端末内・NAS のストリーミング・シーク・再生エラー時の案内・音声
2. 動画 1 本を切って「標準」で書き出す。原本のハッシュが変わらず、出力が再生できること
3. 複数クリップ（縦横の混在・2 倍速・0.5 倍速・回転・埋める）、静止画、文字、音声トラック、フェード
4. 容量指定（目標以内に収まるか、書き出し直しの回数）、音声のみ（.m4a）、HEVC を選んだときの「条件未達」の表示
5. 保存先: 同じフォルダ（同じ名前があるとき）、場所を選ぶ（端末内・Google ドライブなど）
6. 取消（画面のボタン・通知）、書き出し中のアプリの切り替え、画面の消灯、容量不足、書き出し中の素材の削除
7. 書き出し中にアプリを強制終了し、もう一度開いたときの案内と一時ファイルの削除
8. 長さのずれと音ずれ（設計書 §13-3 の暫定目標）
