# Foldex 画像編集 1.8.5 — 下書きの保存と復元

目的は**商用アプリと同等の機能・品質**であり、商用出荷は行わない（2026-09-13 ユーザー指示）。
Foldex 本体は MIT のまま。新規依存・モデル・通信処理の追加はない。

## 操作

- 編集開始時に元画像の不変コピーをアプリ内部へ保存する。以後の描画・出力・撮影情報の読込にはコピーを使い、元ファイルが移動・削除されても下書きから再開できる。
- 確定した編集、選択、文字、出力設定を約 1 秒のデバウンスで自動保存する。画面が背景へ移るときと「下書きを残して閉じる」では保存を早める。
- 「保存中」「保存済み」「保存できない理由と再試行」を表示する。初回の素材保存に失敗しても、そのセッションでの編集と画像出力は続けられる。永続保存ができたとは表示しない。
- ホーム右上メニューの「画像編集の下書き」、または編集画面の下書きアイコンから一覧へ入る。名前、保存日時、件数、使用容量、編集中・破損・非対応の状態を確認できる。
- 一覧から再開・削除できる。編集中の下書きは別の編集画面で開けず、一覧からの削除も拒否する。削除で元ファイルや書き出した画像は消さない。
- 戻る操作で「下書きを残す」「画像として保存」「下書きを破棄」「編集に戻る」を選ぶ。保存・削除に失敗した場合は編集画面を閉じない。
- 画像を書き出した後も編集画面と下書きを残す。画像出力の成功と編集データの削除を連動させない。

## 永続化の内容

`filesDir/image-drafts/<documentId>/` に保存する。OS が回収する `cacheDir` を復元元にしない。

- `assets/<SHA-256>`: 元画像のバイト列。ストリームでコピーし、前後の原本とコピーの SHA-256・サイズを照合する。同じ文書の世代は同じ素材を参照する。別の下書きとは共有しないため、削除の影響を分離できる。
- `manifest-<revision>.bin`: 明示 schema（初期版 1）の DTO と SHA-256。キャンバス、出力設定、画像の変形、ブラシ、文字、塗り、モザイク、複合選択、原本の場所と照合値を記録する。
- JSON は必須にせず、Java 標準のデータ入出力で形式を明示する。Java オブジェクト直列化、反射、enum の ordinal を保存形式に使わない。将来の外部プロジェクト形式 `.foldexedit` とは別の内部形式。
- 全体で 16 MiB / 世代、文字列 1 MiB、レイヤー 10,000、選択の入れ子 64 段などの上限を設ける。素材画像の容量はこの 16 MiB に含まれない。上限やメモリ不足で保存できない場合も、前の正常な世代を維持する。
- 未確定のモザイクプレビュー・進行中の自動推論・表示ズーム・Undo の過去履歴は含めない。復元後の Undo は新しく開始する。

## 中断と競合

素材を先に保存し、世代記録を一時ファイルへ書く。`sync` と読み戻し検査を終えてから同じディレクトリ内で原子的に公開する。正常な最新 2 世代を残す。

新しい保存が終わるまでは前の世代を復元できる。最新世代の破損時は前の正常な世代へ戻したことを案内する。素材の欠落・改変や非対応 schema／効果は黙って読み飛ばさない。破損した最新世代と同じ番号を再利用しない。

同じアプリプロセスの複数画面からも保存・削除を排他する。古い保存要求で新しい世代を巻き戻さず、破棄した文書を遅い保存で再作成しない。残った一時世代と素材コピーの一時ファイルは、利用中でない文書の一覧取得・再開時に回収する。壊れた下書きそのものは勝手に消さず、一覧から削除できる。

## 画像の書き出しとの関係

描画用の不変素材と、元ファイルへの上書き先・照合値を分離した。上書きしても下書き内の素材は変わらず、次の上書きで使う原本ハッシュだけを更新する。

NAS・SAF とローカル上書きでは、保存先と出力ハッシュを下書きへ記録してから配置を行う。結果未確認の記録と撮影情報の警告を復元し、同じ出力を再送せず読み戻して確認できる。SAF は保存先が提供する場合に永続 URI 権限を取得する。権限失効・接続削除時の再検証は失敗として扱う。

下書き自体の保存に失敗した場合は、最後に保存できた記録までが復元対象になる。下書きを作れない状況でも画像の書き出しは妨げないため、全ての保存先・タイミングで出力の受領記録まで残せるとは保証しない。番号を選んで作成するローカルの新規コピーは、配置直前の保存先記録の対象外。
